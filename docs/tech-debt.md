# Tech-debt log

A **buffer, not an archive**. `/review-loop` appends SYSTEMIC findings here instead of iterating on them; `/triage` periodically clusters entries, files root-cause GitHub issues, and **deletes** what it captured. A long-lived entry here means triage is overdue.

Entry format:

```
## YYYY-MM-DD — short title
- Where: file/module references
- What: the pattern or problem (symptom AND suspected root cause if known)
- Source: PR/issue #
```

Pointers must survive unrelated edits: cite **files and symbol or section names** (function names, headings, config keys, script names) — never bare line numbers, and never a copied code literal unless the literal itself is the finding. An entry that pins its claim to `file.sh`:42 sends its reader to whatever happens to sit at line 42 months later. Applies to entries dated 2026-07-31 onward; the back catalogue is retrofitted opportunistically, whenever an entry is edited for any other reason.

## 2026-07-30 — `aws_budgets_budget.cost_types` left at AWS defaults

- Where: `infra/bootstrap/budget.tf` (`aws_budgets_budget.monthly_cost_ceiling`)
- What: no `cost_types` block, so the budget uses the AWS defaults, which subtract credits and refunds. On an account carrying promotional credits the meter can therefore run well past $100/month of gross usage while net cost stays under threshold and nothing alerts — the alarm reports what will be billed, not what is being consumed. That is a defensible reading of "cost ceiling" for a project whose ceiling is about the bank balance, and it is the current deliberate choice; it stops being defensible the moment credits land on the account, because the whole point of the ceiling is to catch runaway usage _before_ it is expensive. Revisit if credits appear (or before any AWS-credits programme is used for this project): either add `cost_types { include_credit = true, include_refund = false }`, or add a second usage-oriented budget beside the billed-cost one. Not a fix for this diff — it is a policy decision about what the number means, and it wants the account's credit state as an input.

## 2026-08-05 — No a11y linting, on the diff that lands the app's first seven interaction patterns

- Where: `eslint.config.mjs` (no `eslint-plugin-jsx-a11y` in its plugin list); the patterns now relying on review attention alone are the disclosure in `HeaderMenu` (`apps/web/src/header/HeaderMenu.tsx` — its `aria-expanded` button and the `onKeyDown` on the non-interactive wrapper `div`), the native modal in `AboutDialog` (`apps/web/src/header/AboutDialog.tsx` — its `aria-labelledby` and `onCancel` wiring), the decorative `aria-hidden` mark in `Brand` (`apps/web/src/header/Brand.tsx`), and — the fourth and by some distance the most intricate — the combobox in `SiteSearch` (`apps/web/src/header/SiteSearch.tsx`: `role="combobox"` with `aria-expanded`/`aria-controls`/`aria-autocomplete` on the input, `aria-activedescendant` pointing into a `role="listbox"` of `role="option"` `<li>`s, one of them `aria-disabled` for the no-match message, and `aria-selected` tracking the highlight), and the fifth, the toggletip in `InfoTip` (`apps/web/src/info/InfoTip.tsx` — its `aria-label` naming the subject rather than the glyph, its `aria-expanded` button, and the `onKeyDown` on its non-interactive wrapper `span`; it is deliberately a disclosure rather than the canonical `role="status"` toggletip, which is the kind of considered deviation a rule set has to be chosen around rather than switched on over), and the two the site table brought with it — the native `<details>`/`<summary>` disclosure and the data table itself (`apps/web/src/dashboard/SiteTable.tsx`: `scope="col"`/`scope="row"` deciding which cells are headers of what, the table's `aria-label`, and `aria-current` on the row buttons)
- What: the repo enforces the frontend gate mechanically for _tokens_ and nothing else — `react.md` rule 5's "if a token is missing, the lint error _is_ the design signal" is scoped to colour and spacing, and no rule in either linter has an opinion about roles, labels, or keyboard reachability. The failure mode is silent and cumulative: each future popover, dialog or custom control copies whatever the first one did, and a regression (a dropped `aria-expanded`, a label that stops matching, a handler that becomes unreachable) is green in every gate. The combobox is the sharpest illustration and arrived with its own worked example: it shipped in review cycle 1 with `aria-activedescendant` set whenever a match existed rather than whenever the popup was _open_, so on every page load the attribute named an element that was not in the document. `axe`'s `aria-valid-attr-value` reports exactly that, `jsx-a11y` does not (the value is computed), and neither is wired up — a reviewer reading the JSX is what caught it, which is precisely the dependency this entry is about. The table members are the second worked example, and a cheaper one to have missed: the row-header semantics its own docblock calls load-bearing shipped with nothing asserting them, so swapping `<th scope="row">` for a `<td>` left every test green and every gate quiet while a screen reader reading across a row stopped being told which site the numbers belonged to.
