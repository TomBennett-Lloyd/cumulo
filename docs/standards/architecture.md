# Architecture standards

**Trigger:** adding a module, package, or service; adding a dependency between packages; restating an owned value (infrastructure, schema ceiling, cost) in code or prose; unsure where new code belongs; changing behaviour that a comment beside it argues for; writing a worked or derived figure into a comment or doc.

## Rules

1. **Dependency direction is one-way.** `apps/*` depend on `packages/*`. Packages never import from apps. Apps never import from other apps — anything two apps need lives in a package. Within a package, modules expose a deliberate surface via `index.ts`; deep imports across module boundaries are a smell.

2. **Domain schemas live in `@cumulo/shared`, once.** Site, forecast, reading — one zod schema each, shared by API validation, queue payloads, and frontend types. If two definitions of the same concept exist, that's a bug even when they currently agree.

3. **Pure core, effectful edges.** PV physics, aggregation math, and error metrics are pure functions of typed inputs — no I/O, no clocks, no env access. AWS clients, HTTP, and Open-Meteo calls live in thin adapter modules at the edges. This is what keeps the interesting code trivially testable and the Lambda handlers boring.

4. **Service boundaries are the ones in the ADR — resist fragmenting further.** Ingestion, forecast, fleet API, web. A new deployable needs an ADR arguing for it (independent scaling/failure/deploy cadence), not just a new concern. New concerns default to new _modules_ inside existing services.

5. **No `utils/` dumping ground.** Name modules by domain (`irradiance.ts`, `aggregation.ts`), not by genericness. If code has no domain name, question whether it belongs here at all. The `check:module-names` gate in `verify` enforces the filename half of this — a bare `utils.*` module fails the build, not just review.

6. **Significant decisions get an ADR** (`docs/adr/`, template there). Significant = expensive to reverse, cross-service, or surprising to a newcomer. The service split, the DynamoDB/Postgres split, and the PV-model runtime are all ADR-worthy; a function's internal shape is not.

7. **Functions by default; a class only where methods genuinely share state.** `this.` is the marker that makes that state visible — which is exactly what a factory closing over variables hides. One **flat** base class is acceptable for shared _mechanism_ that needs instance state (the storage adapters' error-wrapping helper is the motivating example). No hierarchies: a class extending anything other than a base that itself extends nothing is a review blocker (`Error` subclasses excepted). No speculative polymorphism: an abstract method needs ≥2 implementations in the same PR. And a detached method loses its `this`, so inject the object, not the method — `@typescript-eslint/unbound-method` enforces that.

8. **A constant that mirrors an infrastructure value is declared to the mirror gate.** Some numbers genuinely live in two places — Terraform owns the deployed value, and code has to size itself against it (`INGESTION_LAMBDA_TIMEOUT_MS` against `aws_lambda_function.ingestion`'s `timeout`). That is allowed, and citing the other file in a comment is not enough: comments do not fail builds. Add the pair to `MIRRORS` in `.claude/scripts/check-infra-mirrors.sh`, which the `check:infra-mirrors` gate in `verify` compares on every run. The gate only knows the pairs it is told about, so declaring one is the part that cannot be automated — and an undeclared mirror drifts silently, in whichever direction nobody was watching.

9. **A stated value has one owner; prose points at it, never restates it.** Every fact that reads as a value or a name — a capacity, a ceiling, a transport, a billing mode — has exactly one owning declaration: an exported constant, a Terraform attribute, one named comment block, or one named doc section. Any other mention names the owner (`MAX_PLAUSIBLE_RESIDENTIAL_KW`; "`infra/storage/tables.tf`'s header") and carries no literal of its own. A site that must carry the literal because it computes with it or asserts it (a cost table, a runbook readback expectation) is listed in a short **restatement ledger** comment beside the owner, so changing the owner finds every copy at plan time rather than serially in review (#156). An **arguing** site — prose that must quote the value to reason from it — is listed in the ledger the same way as a computing or asserting one; rule 11 gives its truing to the change that moves the value, and `docs/standards/security.md` rule 1 is the worked case. A value acquires its ledger the first time a second site is found carrying it, and the finder writes it: a review's claim sweep ends in the owner's ledger, not only in the finding (#356 rebuilt the same sweep three times and still missed members). A ledger declares itself a floor and names its sweep — the pattern run and the date — because an enumeration claiming completeness is falsified by one more carrier, while a floor naming its sweep is not (#295). Rule 8's mirror gate is one example of mechanical coverage — `check:infra-mirrors` compares every declared code↔Terraform pair (numeric and string) on every run — but no gate in `verify` compares a prose mention against its owner, which is why the ledger is the discipline that carries it. Historical claims survive in past tense, naming the decision they reason about. An ADR's **decision and reasoning** are immutable and exempt, and the exemption stops there: a **stated value an ADR owns** is amendable (`docs/adr/README.md` § Amendments) and sits inside this discipline like any other owned value, its restatement ledger living in that ADR's `## Amendments` section — the section an amendment is already obliged to write. A citation of such a value, from another ADR or anywhere else, names the owning section and carries no literal, unless it computes with, asserts, or argues from the figure, in which case the owner's ledger lists it like any other carrier.

10. **Changing an owned value is the other direction of rule 9, and it has its own sweep.** A true-up's blast radius is not the set of places containing the old literal. It also holds every figure _derived_ from that value — ratios and deltas whose operands moved, counts of the sites restating it, prose adjectives quantifying it ("roughly a third", "six times cheaper"), and present-tense quotations of the sentence it lives in. None of those contain the old literal, so no grep for it reaches any of them; and carriers that _paraphrase_ rather than quote are invisible to a sweep keyed to the owner's phrasing, so shape the sweep around the claim instead. Before editing, enumerate the carriers and the derived figures by a stated grep, and let every expected count **name its surviving occurrences** rather than only counting them — a bare count is satisfiable by the wrong survivors. Evidence: PR #389, where re-basing one rate silently falsified a `3.5×` ratio, a `≈ $65` delta, an exactly-six "six times cheaper", three prose characterisations and a sibling ADR's present-tense quotation, each found a review cycle after the last; and PR #385, where three paraphrasing carriers survived two sweeps that had already called the family clean.

11. **A comment that argues for a behaviour is a carrier of that behaviour.** Rule 9 gives a claim's carriers to the change that moves the claim; an argument's carriers carry the same obligation. When a change removes or reverses behaviour that a comment or docblock beside it defends, that prose is part of the change surface: enumerate it before editing and true it in the same change, and hold the replacement prose to the code's standard of evidence — it is the part of the diff most likely to assert something false. Evidence: #367/PR #394, where `layoutBoxOf`'s docblock explicitly defended the racing two-read shape the ticket removed, and the defect recurred twice inside the same ticket — review cycle 1 found three inaccuracies in the replacement prose, and cycle 2 found that cycle 1's own new tech-debt entry asserted something false. A surviving argument for deleted behaviour is a documented trap: the bug on a delay.

12. **A figure that exists only because someone computed it is owned by nothing.** Rules 9 and 10 both start from an owning declaration — one to point at instead of restating, one to sweep outward from when it moves. A worked example, a counterfactual configuration's result, a count, an input tuned so an example lands where the case needs it: none of these is declared anywhere, so there is no owner to name in the literal's place and no owner's edit for a sweep to begin at. Nothing in `verify` pins such a figure either, so it does not rot loudly — it rots green, and a worked number that is still right is indistinguishable on sight from one that stopped being right. The test is whether the prose **reasons from** the figure or merely **illustrates with** it. Reasoning is written as the expression that derives it, or stated qualitatively: an owner's docblock states its meaning as an expression rather than quoting its own output, and a counterfactual the code cannot exercise gets no specific number at all, being unfalsifiable by construction — no reader, no test and no gate can catch it going wrong. Illustration degrades to an ageless magnitude ("thousands"), which needs no re-measurement and so can never fall behind one. A tuned input is the member no sweep reaches, because it carries neither the value it depends on nor any phrasing of it; name what it is tuned against, beside the example or in the owner's restatement ledger, since retuning that value leaves the case not failing but green and demonstrating nothing — the silent outcome, and the reason the dependence has to be written down where reading the example will find it. Any carrier list this prose contains takes rule 9's floor-not-census form, by pointer rather than by restatement. The neighbouring discipline is `docs/standards/evidence.md`, which governs command output offered as proof; the boundary is that a figure written into standing prose is offered as proof of nothing and simply ages. Evidence: #295/PR #398, whose confirmation rounds repeatedly falsified a figure written by the round that fixed the one before, and which terminated by eliminating figures rather than by pinning them; and #388, which committed a wrong count inside the PR that logged the wrong-count pattern — `docs/friction-log.md`'s 2026-08-11 entries own both records. Worked cases: `packages/shared/src/simulated-uncertainty.ts` and `stylelint.config.mjs`.

## Why

The job this repo showcases values judgement about boundaries: a small number of genuinely independent services, documented reasoning, and restraint about further splitting. The pure-core rule is also what makes the physics-vs-ML comparison feature cheap to build — both layers are pure transforms over the same typed inputs.
