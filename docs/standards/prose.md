# Prose — code comments, docblocks, and standing documentation

The unit of value is the claim, not the line. Standing prose is a liability that must earn its keep: nothing in `verify` fails when it rots. These rules keep the prose surface small enough to sweep and true — and they bind `.claude/` skills, agent docs, and `docs/` exactly as they bind source, because process prose rots the same way.

## Rules

1. **The code explains itself first.** A comment is the fallback, not the default: prefer a name that carries the meaning — a well-named constant over a comment defining one, a small named helper over a paragraph narrating a block. A long docblock on ordinary code is a smell that the code wants restructuring, not narrating. What earns lines: constraints the code cannot express, invariants, and the why behind a non-obvious choice. What never does: restating what the code visibly says.

2. **Figures live in tests, not prose.** A measured or derived figure — a pixel, a count, a threshold, a duration — appears in standing prose only when a named test or gate asserts it, or when it is approximate by form (`~330 kW`, "thousands") and survives any plausible drift. Otherwise the number goes into a test and the prose keeps the argument: a figure in a comment rots silently, the same figure in a test fails loudly. When a measured value moves, the edit is to the asserting test; prose that named the test needs nothing. Worked examples and tuned inputs have their own mechanics in `docs/standards/architecture.md` rule 12.

3. **References are greppable, never paraphrased.** Prose that refers to other code names it verbatim — the repo-relative path (`apps/web/src/dashboard/fleet-panel.css`) or the exported identifier (`CHART_VIEW_BOX_HEIGHT`) — and does not restate what it says. Changing X then finds every comment about X mechanically: `git grep` for X's path and symbols is the sweep. A bare basename is permitted only for a same-directory sibling — the one form that cannot collide; every other file is named by its repo-relative path (#482). A paraphrase ("the stylesheet that sizes the row") is invisible to every sweep and rots without a trace. Owned values additionally keep architecture.md rules 8–10's mirror-gate and ledger machinery; this rule governs the references that machinery does not reach.

4. **Architectural reasoning cites the record.** Where the why is a recorded decision, write one sentence of local relevance and cite the owner — an ADR by filename, or a standard's rule by number. Restating the argument inline creates a second copy that drifts from the first.

5. **Condense on touch.** Editing a file makes its prose part of the edit: trim what the code now shows, convert paraphrases to verbatim references, move figures into the tests that assert them. Wholesale trims of untouched files are campaign work (#467), never drive-by scope.

## Why

Adopted by owner decision, 2026-08-25 (#464). At adoption, 45% of `apps/web/src` was comment lines; review loops converged on prose findings while finding zero behaviour bugs; and the period's one serious defect was environmental — a class no prose-reading review can catch. The prose surface had become the main cost of every change without being the main source of risk.

## Trim batches

A PR whose diff `.claude/scripts/verify-tier.sh` classifies `source-prose` or `docs` is a trim batch, and runs under a stricter contract than a feature PR, because its whole risk is prose minted while removing prose (#486 classified eighteen review findings across the first two batches: five were deleted sole carriers, eight were claims written by the fix rounds themselves, thirteen were reproducible by a command).

1. **Delete or cite, never rewrite.** A trim deletes a sentence, replaces a figure with the name of the test or owner that asserts it, or replaces a paraphrase with the verbatim path or identifier. It does not rephrase. The one exception is a restatement ledger `architecture.md` rule 9 obliges the finder to write, held to rule 3 below. A fix round restores a deleted carrier verbatim from the base (`git show <base>:<path>`), never in fresh words.
2. **A deletion ledger precedes review.** Every deleted claim naming a figure, a path, an identifier, or a _because_ gets one line — `path:line` → shown-by-code (which line) | asserted-by-test (file, case) | cited-at (owner) | illustrative — in the implementer's report and the PR body. The reviewer verifies dispositions; it does not rediscover them.
3. **Mechanical pre-checks, output pasted, before review.** (a) Inbound references: `git grep -n <identifier> -- ':!<file>'` for every trimmed docblock's subject, every hit read. (b) Every new or changed ledger's sweep run with `-n`, carriers enumerated from the output, plus a positive control naming one carrier the pattern must return. (c) No spelled-out figure enters a comment: `git diff <base> | grep -E '^\+' | grep -iE '\b(one|two|three|four|five|six|seven|eight|nine|ten|twenty|thirty|forty|fifty|sixty|ninety|hundred)[- ](second|minute|px|pixel|ms|kW|sites?)'` returns nothing. (d) Every quoted string in a new `docs/tech-debt.md` entry greps to the file it names. (e) Comment reflow: no comment line of three words or fewer ending without punctuation ahead of a full-width continuation — prettier does not reflow comments.
4. **The reviewer's object is the ledger.** Cycle 1's dispatch names the deletion ledger and the pasted check outputs: confirm each disposition, re-run each sweep, then read the diff for what the ledger omitted. An undispositioned deletion, or a wrong disposition, is FIX-NOW; the rest follows `.claude/skills/review-loop/SKILL.md`'s SYSTEMIC rule.
5. **Cap: one full pass and one scoped confirmation.** A second CHANGES REQUESTED on a trim batch is a retro signal that this contract leaked, not a third round.
